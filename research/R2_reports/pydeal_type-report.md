## Overview (what the project does, research question)

**Research question:** How do states construct or contest **social facts** about other states
through diplomatic rhetoric in UN General Assembly (UNGA) speeches, and when is one state
explicitly portrayed as taking **aggressive or malicious action** against another?

The project is a mixed **constructivist-International-Relations (IR) theory + LLM extraction
pipeline**. It ingests chunked UNGA speeches, runs one or more Cohere LLMs over them, and
classifies each *source → target* mention as aggressive/antagonistic (binary 0/1), extracting the
victims and a one-sentence reasoning string per record. Downstream, the aggregated classifications
feed network analysis (accusation networks over time), "top-tier" structural analysis, and a series
of paper-level figures (domestication, long-tail distribution of antagonism, USA–China accusation
network, worldmap of accusation density).

**Two-phase design** is visible in the repo:

1. **Phase 1 (Jan 2025)** — a *typology-building* pipeline using 4 prompts in a ladder of
   abstraction: `prompt1` (extract the single-sentence "rhetorical action" per speech),
   `prompt2` (abstract into document/state-level *ideal types* via Weber), `prompt3` (year-level
   parent types), `prompt4` (classification into an established schema with a `schema_evaluation`
   fit score). This phase lived under `scripts/` + `prompts/` and produced the `runs/ungdc_*`,
   `extended_test*`, and `test*` directories.
2. **Phase 2 (Feb 2025, and the "big push")** — a *binary single-state classification* pipeline
   centered on the USA case (`runs/USA_01/prompt/aggressor_*`), with many parallel prompt variants
   (aggressor, victim, contested-state, ideal-year, social-fact, apply-ideal). The most developed
   variant is `aggressor_05`, which processed the full 1946–2022 corpus (~21,400 records) with two
   different Cohere models (command-r7b and command-r-plus) on the **same** input — the core
   asset for confidence triage. Evaluation (Mar 2025) then compared the two models' outputs and
   human-annotated samples.

The codebase is **strongly prompt-driven**: every prompt variant directory is a self-contained,
independent batch-pipeline (`loader.py`, `processor.py`, `batch_processor.py`, `file_merger.py`,
`arg_parser.py`, `pipeline.py`) that deliberately duplicates core modules so variants could be
iterated "without shared-code coupling."

     prompt on 2022 data, both models), plus `randomrun_commandrplus/`.

4. **`evaluation/` — the explicitly constructed multi-model comparison frames.**

## Confidence Triage Opportunity

The repo contains everything needed to triage extraction/classification confidence by **agreement
across models** (and across runs), and it already did a version of this:

- **Per-record two-model labels on the full corpus:** join `full/ungdc_commandr7b_{year}.jsonl` ×
  `parsed/ungdc_commandrplus_{year}.jsonl` on `doc_id`/`chunk_id`. Agreement (both=1, both=0) =
  high confidence; disagreement (one=1/one=0) = ambiguous, needs review. Because these cover
  ~21,400 records over 1946–2022, this gives a **large, naturally-split confidence signal**.

- **Existing triage implementation to build on:** `evaluation/evaluation_01.ipynb` already
  computes:
  - `classification_clean_r7b_1 / _r7b_2 / _rplus_1` columns;
  - **`across_dataset_agreement`** = `PP / NN / PN / NP` (Test1-vs-Test2 consistency);
  - **`across-model_agreement`** (R Plus Test1 vs R7B Test2);
  - `model_coverage_breakdown()` and `add_agreement_variables()` functions.
  - It also produced `false_positive_rates.png` and `top_tier_accuracy.png` (evaluation/).
  - `evaluation/evaluation_02.ipynb` adds **intra-coder reliability** (prompt-stability) analysis.

- **Malformed tracking:** `full/complete_v2_malformed.jsonl` + a `malformed` column lets you drop
  records with broken/empty outputs before trusting agreement.

- **Human ground truth:** `evaluation/sampling/evaluation_sample_20250323_143756.jsonl` and the
  annotated `..._annotated_20250323_152133.jsonl` (plus `..._annotated_20250323_201957.jsonl` in
  `evaluation/`) provide human judgments usable to *validate* the model-agreement triage (a human
  can arbitrate PN/NP and confirm PP).

**Recommended triage recipe (all data already present):** aggregate per `chunk_id` →
`{r7b_label, rplus_label}` → label high-confidence where they match, flag disagreement for human
review, and use the annotated evaluation sample to estimate P(agreement | ground-truth-correct) to
calibrate the threshold.

## Training-Data Potential for Finetune

Strong, and already partially converted. Formats available:

1. **`runs/USA_01/prompt/aggressor_05/output/adaption_test_dataset_v1.csv`** — **the ready-made
   supervised set.** 100 rows (header `prompt,context,output`), columns:
   - `prompt` — reconstructed full prompt (system + user template with `{text}`/`{target}` injected);
   - `context` — raw speech excerpt;
   - `output` — full LLM `full_response`.
   - Built by `analysis/build_adaption_dataset.py` with seed 42, **class-balanced 40 positive /
     60 negative**, speaker and target caps (≤3 each), ≥1 example per decade (1940s–2020s), and
     both Cold-War and post-Cold-War eras. This is already in an instruction-style
     `prompt → context → output` format suitable for SFT.

2. **`runs/USA_01/prompt/aggressor_05/output/full/complete_v2.jsonl`** (and `complete_v1.jsonl`,
   and the per-year `ungdc_commandr7b_*.jsonl`) — the **full labeled corpus**: fields
   `doc_id, chunk_id, source, year, chunk_start, chunk_end, original_text_length, text, target,
   full_response, classification, victims, reasoning, malformed`. This is `(text,target) →
   (classification, victims, reasoning)` — i.e. clean supervised training data for the
   aggressor-classification task, and the `text`/`target` are injected into `system_prompt.txt` +
   `user_prompt.txt` to rebuild exact prompts.

3. **`evaluation/evaluation_sample_*.jsonl`** — a human-annotated sample (see `sampling/` and
   `evaluation/`) that can serve as **held-out validation / test** and as the arbitration set.

4. **`data/processed/prompt1_batch_*.jsonl`** — phase-1 prompt1 outputs
   (`source,target,year,response`), useful if you want the social-fact sentence task as auxiliary
   data (multi-task).

**Task design options:** the primary task is a structured binary classification with
victims + reasoning extraction. `complete_v2.jsonl` gives ~21,400 records; the adaption CSV gives a
curated, balanced, decade-anchored 100-row slice ready to feed a finetune now; and agreement between
r7b/rplus can be used to **filter the ~21k into high-confidence training labels** (pseudo-labeling
with disagreement removed) before finetuning.

## Lessons & Divergent Paths

Reconstructed from git messages, dir contents, and configs:

- **Divergence A — typology-building vs single-state classification.** Phase 1 (prompts 1–4, a
  theory-driven "ladder of abstraction" producing ideal types) was the original approach, but the
  repo visibly **pivoted (2025-02-04 commit: "moved towards single country focus within runs")** to a
  simpler, more tractable **binary aggressor/victim classification** in `runs/USA_01`. The
  typology prompts remain in `prompts/` and the phase-1 runs, but the main energy went to USA-focused
  classification. This pivot is the project's central lesson: the theory-heavy typology was
  de-emphasized in favor of a clean binary extraction task.

- **Divergence B — the `victim` framing.** Multiple victim variants (`victim_01/02/03`,
  `aggressor_victim_01`, `rus_victim_01`) show he was testing whether to label the *target-as-aggressor*
  or *target-as-victim*; `aggressor_*` became the primary line, victim runs appear exploratory/partial.

- **Divergence C — model choice.** Started with r7b everywhere, then ran **r-plus as a second
  opinion** on the same data (aggressor_02/05, victim_01). This produced the two-model corpus that
  the Mar-2025 evaluation then turned into agreement/accuracy analysis. The lesson that stuck:
  **multi-model runs for robustness** — worth keeping for finetune label triage.

- **Abandoned/backup artifacts:** `scripts/pipeline_backup.py`, `runmanager_backup.py`,
  `aggressor_03/output - Copy/`, `output/merged_backup/`, `overcomplicated/` (a feature-engineering
  + hierarchical-clustering branch inside `analysis/20feb2025`, with its own `pipeline.py`) — all
  evidence of approaches tried then shelved.

- **What stuck:** the modular per-variant batch pipeline (`loader → batch_processor → processor →
  file_merger`), resumable via `tracking.json`; the XML-tag structured output
  (`<CLASSIFICATION>`, `<VICTIMS>`, `<REASONING>`) that enables robust regex parsing; the
  `analysis/build_adaption_dataset.py` pipeline that converts raw JSONL into a clean
  prompt/context/output SFT CSV; and the Command-A QC plan in `plan_tomorrow.md` (a pattern for
  LLM-as-judge verification of generated training rows).
